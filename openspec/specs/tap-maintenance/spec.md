# Tap Maintenance Specification

## Purpose
How the `Yoda-Man/homebrew-yodaman` tap is kept in step with YodaMan releases. The formula is generated in the YodaMan core repository by `scripts/brew-formula.js` and copied here. The tap holds `Formula/yodaman.rb`, `README.md` and `LICENSE`.

## Requirements

### Requirement: Formula moves only after npm publish
The tap's formula MUST name a version that is already published to npm. Its `url` and `sha256` SHALL be generated by YodaMan core's `node scripts/brew-formula.js` from the published tarball, never typed by hand, and copied into `Formula/yodaman.rb` after `npm publish`.

#### Scenario: Release
- **WHEN** a new YodaMan version is published to npm
- **THEN** the maintainer runs `node scripts/brew-formula.js` in core, which fetches `https://registry.npmjs.org/yodaman/-/yodaman-<version>.tgz`, hashes it with SHA-256 and rewrites the formula's `url` and `sha256`
- **AND** the result is copied here and committed as `yodaman <version>`

#### Scenario: Version not published yet
- **WHEN** the tarball for core's `package.json` version cannot be fetched
- **THEN** the script prints `Could not fetch the published tarball: <reason>` and `If yodaman@<version> is not published yet, publish first, then run this.`, and exits 2 (1 with `--check`)

### Requirement: Check without writing
`node scripts/brew-formula.js --check` in core SHALL compare the formula with the published tarball without writing, exit 0 when they match, and exit 1 when they do not.

#### Scenario: Up to date
- **WHEN** the formula already names the published tarball and its hash
- **THEN** the script prints `Formula matches yodaman@<version> (sha256 <first 12 hex>…)` and exits 0

#### Scenario: Out of date
- **WHEN** the url or sha256 differs from the published tarball
- **THEN** the script prints `Formula is out of date for yodaman@<version>.` and `Run: node scripts/brew-formula.js`, and exits 1

### Requirement: Same formula in both places
`Formula/yodaman.rb` in this tap MUST be identical to `packaging/homebrew/yodaman.rb` in YodaMan core after each release.

#### Scenario: Drift between copies
- **WHEN** the two files differ
- **THEN** the tap is not in step with the release and must be updated from core's copy

### Requirement: Install instructions
The tap's README SHALL give the install commands `brew install Yoda-Man/yodaman/yodaman`, or `brew tap Yoda-Man/yodaman` then `brew install yodaman`, and SHALL point to `yodaman setup` for the companion tools.

#### Scenario: Reading the README
- **WHEN** a user opens the tap's README
- **THEN** it shows both install forms and the `yodaman setup` step, and says Ollama is not installed automatically
